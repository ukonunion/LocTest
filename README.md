# LocTest 1.0 — консоль и производительность сервера

Обновление существующей версии 1.0: консоль слева, справа изменяемая по ширине
панель в стиле Performance из Диспетчера задач. Светлая и тёмная темы
переключаются в верхней строке; выбор сохраняется в `theme.txt`.

## Показатели справа

- **CPU сервера** — изменение процессорного времени именно запущенного процесса,
  в процентах от суммарной мощности всех логических CPU. Не загрузка всего компьютера.
- **Память JVM** — фактически используемый heap / максимальный heap JVM (`-Xmx`).
  Отдельно указан committed heap. Это не RSS процесса и не память всего компьютера.
  Лимит читается из самой серверной JVM, поэтому учитывает переопределения аргументов.
- **Игроки** — число онлайн и лимит из стандартного ответа консольной команды `list`.
- **TPS** — реальное среднее за 1 минуту из ответа `tps` на Paper/Spigot-совместимом ядре.
  Это не оценка TPS по CPU или миллисекундам тика.
- PID, время работы, количество потоков JVM и суммарное время GC.

CPU/память обновляются каждую секунду, графики показывают 60 последних измерений.
Память, потоки и GC собирает небольшой встроенный Java-агент (Java 8+), который
панель подключает в режимах JAR/JAVA_ARGS. Он не меняет байткод и не открывает
сетевой порт: записывает только локальный файл в `<сервер>/.loctest/`.
В COMMAND агент автоматически не подключается, heap может быть недоступен.
При запуске оболочки CPU/PID относятся к оболочке, а не к отделённым дочерним процессам.

После готовности сервера каждые 5 секунд панель посылает `list`. Команда `tps`
добавляется после распознавания баннера Paper/Purpur/Spigot или ответа на вручную
введённую `tps`. Ответы остаются видны в консоли. Разбор рассчитан на стандартные
английские ответы; для неподдерживаемого ядра или изменённого формата — «Нет данных».
Данные игроков/TPS устаревают через 15 секунд, heap — через 5 секунд. При остановке
и новом PID показатели сбрасываются. Нулевые значения не подставляются вместо неизвестных.

## Цвета консоли

ERROR/FATAL/SEVERE — красный; WARN/WARNING — жёлтый. В светлой теме у WARN
жёлтая подложка и более тёмный текст для читаемости. INFO — обычный цвет темы.
При смене темы перекрашиваются также уже выведенные строки. Если пользователь
отошёл от конца консоли, новые строки не переводят курсор в конец принудительно.

## Установка обновления и история

Закройте старую панель, замените старый PaperLab/LocTest JAR в `mods` новым.
Номер остаётся **1.0**, поэтому ориентируйтесь на обновлённый файл GitHub Release.

| Версия | Возможности |
|---|---|
| 0.7 | Локальный Paper (бывшая PaperLab 1.0.0) |
| 0.8 | Разные серверные ядра (бывшая 1.1.0) |
| 0.9 | LAN-порты (бывшая 1.2.0) |
| 1.0 | Консоль, темы и серверный мониторинг |

Каждый тег содержит исходники своей версии. Новая установка использует `loctest`;
существующая папка `paperlab` продолжает использоваться для совместимости.
Namespace Java и имена файлов настроек сохранены. В путях ниже `paperlab` также
означает `loctest` для новой установки.

Проверено: чтение настоящего heap из тестового дочернего Java-процесса, запуск
и остановка, очистка устаревших данных при остановке, разбор игроков/TPS,
цвета консоли, расчёты CPU, отрисовка обеих тем и прежние тесты запуска/портов.
Полный запуск в Minecraft и проверка на настоящем серверном ядре не выполнялись.

## Установка

Удалите предыдущий JAR LocTest из mods и положите туда
loctest-1.0+26.3.jar. Нужны Fabric Loader 0.19.5+ и Java 25; Fabric API не нужен.
Запустите игру, переключитесь на окно LocTest и нажмите «Ядро и запуск».
После настройки прочитайте Minecraft EULA, отметьте согласие и запустите сервер.
Старый paperlab/paper.jar подхватывается автоматически при отсутствии настроек.

## JAR — обычный сервер

Подходит для исполняемых JAR: Paper, Purpur, Spigot, Vanilla, Fabric Server
Launcher и других ядер с запуском java -jar. Выберите папку сервера, Java,
серверный JAR и память. В аргументах запуска обычно оставляют nogui.

JAR не копируется: он запускается с выбранного пути, а рабочей папкой становится
«Папка сервера». Сохраните там библиотеки и конфиги установки. Для Fabric
выбирайте Server Launcher, а не установщик. Наличие нужной версии ядра
проверяйте у его автора. Для другого ядра используйте отдельную папку мира.

Команда: Java -Xms512M -Xmx<RAM>M [JVM] -jar <JAR> [аргументы запуска].

## JAVA_ARGS — Forge, NeoForge, нестандартный запуск Java

Сначала установите сервер штатным установщиком. Укажите папку установленного
сервера и подходящую Java. В поле «Запуск» перенесите аргументы из run.bat/run.sh,
без слова java, без %* и без команд оболочки. Например, для NeoForge на Windows:

```text
@user_jvm_args.txt
@libraries/net/neoforged/neoforge/ВАША_ВЕРСИЯ/win_args.txt
nogui
```

Используйте реальные пути из вашей установки. На Linux обычно нужен unix_args.txt.
RAM и JVM-аргументы панели добавляются первыми; -Xmx из user_jvm_args.txt может
их переопределить. Настраивайте память в одном месте. Панель не устанавливает ядра.

## COMMAND — произвольный исполняемый файл

В «Java / программа» укажите программу, в «Запуск» — её аргументы.
RAM, JVM и JAR в этом режиме игнорируются. Оболочка автоматически не вызывается:
переменные, && и перенаправления не раскрываются. Для скриптов нужно явно указать
интерпретатор. Предпочитайте прямой запуск серверного процесса; не используйте
скрипты, которые отсоединяют сервер в фон, иначе консоль и остановка не управляются.

Во всех полях аргументов действует правило: ОДИН АРГУМЕНТ НА СТРОКУ.
Пути с пробелами вводятся без внешних кавычек. Например:
@C:\Мой сервер\args.txt — одна строка и один аргумент Java.

Для нестандартных ядер/прокси задайте их команду остановки (по умолчанию stop)
и маркер готовности — фрагмент строки лога. Пустой маркер показывает «Процесс
работает» без проверки готовности. Выключите изменение server.properties,
если ядро использует другой конфиг, и настройте его адрес/порт самостоятельно.

Универсален механизм запуска, а не совместимость любого ПО: необходимы
рабочая установка ядра, правильная Java/среда и аргументы.

## Подключение и версии

При включённых локальных настройках панель задаёт в server.properties
server-ip=127.0.0.1 (или пустой адрес при включённом LAN), выбранный порт (по умолчанию 25575), выключает RCON и query.
Прочие существующие значения сохраняются; online-mode=true — значение по умолчанию.
При снятой галочке server.properties не меняется: доступ по сети определяется ядром.

В Minecraft: Сетевая игра → Прямое подключение → 127.0.0.1:25575
(или ваш порт). Для иной конфигурации используйте адрес ядра.

Сам мод — для Fabric 26.3. Ядро может быть другой версии, но для входа нужен
совместимый клиент, а для модовых серверов — подходящие загрузчик и моды.
Панель требует Java 25; серверу можно назначить другую Java через настройки.
Без Minecraft панель запускается так:

```powershell
java -Djava.awt.headless=false -jar loctest-1.0+26.3.jar "C:\MinecraftTests\launcher"
```

## Моды, плагины, отчёт

«Добавить плагины» проверяет наличие plugin.yml, paper-plugin.yml, bungee.yml
или velocity-plugin.json и копирует JAR в plugins. «Добавить моды» проверяет
читаемость JAR и копирует его в mods. Совместимость загрузчика/версии не проверяется.
Добавление доступно при остановленном сервере. Старый файл не перезаписывается:
для обновления удалите прежний JAR вручную через «Папка сервера».

Поддержка плагинов определяется ядром: обычные Vanilla, Fabric, Forge и NeoForge
не становятся совместимыми с Paper-плагинами при запуске из панели.
Используйте доверенные файлы: отдельный процесс не является песочницей.

Команды консоли вводятся в нижнее поле без /. «Отчёт» создаёт report.txt:
состояние, описание запуска, дескрипторы плагинов и до 5000 строк диагностики.
Полный вывод последнего запуска — session.log. Следующий запуск заменяет лог,
следующий отчёт заменяет report.txt. Маркер готовности не гарантирует исправность
модов/плагинов: игровые сценарии нужно проверять в игре.

## Настройки и остановка

Последняя конфигурация сохраняется в <профиль Minecraft>/paperlab/launcher.properties,
там же находится panel.log. Мир, EULA, плагины, моды, логи и отчёт находятся
в выбранной папке сервера. Настройки меняются после остановки сервера.

Закрытие Minecraft не останавливает панель. «Остановить» посылает выбранную
команду. При закрытии панели она ждёт 30 секунд, затем завершает зависший процесс;
при принудительном завершении последние изменения мира могут не сохраниться.

## Сборка и проверка

Нужен JDK 25 с java/javac/jar в PATH. Выполните .\build.ps1.
Скрипт скачивает официальный Fabric Loader 0.20.1 для компиляции, собирает JAR
и запускает тесты. Для сборки без сети передайте -LoaderJar "путь\fabric-loader.jar".
Fabric Loader в итоговый мод не встраивается.

На тестовых Java-процессах проверены все три режима, исполняемый JAR, @argfile,
пути с пробелами, передача аргументов без оболочки, сохранение конфигурации,
свои команда остановки/маркер готовности, повторный запуск, ошибки и отчёт,
отказ без EULA и включение/отключение изменения server.properties.

Настоящие ядра Minecraft, интерфейс и загрузка мода в Fabric в этой среде
не проверялись. Тесты проверяют механизм запуска, а не все серверные сборки.

Официальные справки:
- https://fabricmc.net/use/server/
- https://docs.neoforged.net/user/docs/server/
- https://docs.papermc.io/paper/getting-started/

## Новое в 1.2: дополнительные порты Windows

1. Остановите сервер, если будете менять его адрес привязки.
2. Откройте **Порты…** и введите по одному правилу на строку:

```text
TCP 25575
UDP 24454
TCP 8123
```

Это только пример списка: выбирайте фактические порты ваших сервисов.
Поддерживаются отдельные номера 1–65535 и протоколы TCP/UDP, до 64 правил.
Одинаковые строки объединяются, TCP и UDP одного номера остаются разными правилами.
Кнопка «+ порт сервера» добавляет текущий игровой TCP-порт.

3. Для доступа к основному серверу из LAN отметьте **Разрешить ядру слушать сеть**.
   Это меняет server-ip на пустой при следующем запуске, если включено управление
   server.properties в «Ядро и запуск». При ручной конфигурации ядра или прокси
   настраивайте его адрес привязки сами. Для возврата к localhost снимите галочку
   при остановленном сервере, сохраните и запустите сервер снова.
4. Нажмите **Применить правила** и ответьте на запрос администратора Windows.
   **Сохранить** отдельно сохраняет только список/настройку LAN, без изменения брандмауэра.
5. Настройте дополнительные порты и адрес прослушивания в соответствующих плагинах
   или модах. Запустите сервер. Другой компьютер подключается к локальному IP
   этого компьютера, а не к 127.0.0.1.

Правила разрешают входящий трафик **только из локальной подсети**, для профилей
Windows **Частный** и **Доменный**. В профиле **Общедоступный** эти правила
не действуют. Панель не меняет тип сети Windows, правила роутера или проброс в интернет.
Создание правила не запускает слушающий сервис, не резервирует порт и не
подтверждает доступность с другого компьютера. Запрещающие правила Windows
или сторонний брандмауэр могут по-прежнему блокировать соединения.

Настройки хранятся в `paperlab-network.properties` выбранной папки сервера.
Правила Windows сохраняются после закрытия панели. Повторное применение заменяет
правила LocTest этой папки актуальным списком, удаляя ранее добавленные порты,
которых в списке больше нет. При ошибке возможно частичное применение — панель
покажет это; повторите применение либо удалите правила.

**Удалить правила** удаляет только правила LocTest выбранной папки.
Правила других приложений и папок не затрагиваются. Это не гарантирует блокировку
порта, если его уже разрешает другое правило. Перед переносом/удалением папки
сервера удалите её правила: принадлежность правил определяется путём папки.

Проверено: валидация портов, сохранение настроек, переключение LAN/localhost,
изоляция групп правил, синтаксис PowerShell, применение и удаление на подставных
командах PowerShell. Реальный брандмауэр во время тестов не изменялся;
повышение прав через UAC и подключение с другого компьютера не проверялись.

Справка Windows:
- https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule
- https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process
